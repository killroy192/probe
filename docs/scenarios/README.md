# User scenarios

Each file here is one user goal of the built product: its workflows as the user does them, and
numbered functional (FR) and non-functional (NFR) requirements. The scenario tests cite these
requirements as `<slug>/FR-<n>` or `<slug>/NFR-<n>`, where `<slug>` is the file name, for example
`shells/FR-3`. How to write one: [scenario-docs rules](../../.agents/rules/scenario-docs.md).

| Scenario                                    | Goal                                            |
| ------------------------------------------- | ----------------------------------------------- |
| [workspaces](workspaces.md)                 | Keep work in named workspaces                   |
| [projects](projects.md)                     | Add projects to a workspace                     |
| [shells](shells.md)                         | Run many shells side by side                    |
| [starting-scripts](starting-scripts.md)     | Choose what a new shell starts                  |
| [worktrees](worktrees.md)                   | Run shells in worktrees                         |
| [close-and-reopen](close-and-reopen.md)     | Close a tab and reopen it                       |
| [kill-shell](kill-shell.md)                 | Kill a shell and see what ended                 |
| [restore-shell](restore-shell.md)           | Restore an ended shell                          |
| [reload-and-restart](reload-and-restart.md) | Keep shells running across reloads and restarts |
| [second-server](second-server.md)           | Run a second server beside the first            |
